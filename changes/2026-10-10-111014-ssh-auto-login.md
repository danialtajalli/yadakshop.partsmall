# SSH Automatic Login Setup

## Request and Target

Set up automatic SSH login from this Windows machine to the user-provided server
`ubuntu@130.185.122.197`. Use a dedicated SSH key and the alias `partsmall-server`.

## Actions and Changed Files

- Read the Partsmall agent policies before beginning.
- Confirmed that the server IP and `partsmall.ir` have the same existing trusted
  Ed25519 host key in the local `known_hosts` file.
- Attempted password authentication twice, including once with UTF-8 terminal
  encoding. Both attempts were rejected by SSH. No further password retries were
  made, and the supplied password was not saved to a file or SSH configuration.
- Generated a dedicated Ed25519 key with no passphrase for unattended login:
  `C:/Users/BABAK/.ssh/partsmall_server_ed25519` and its `.pub` public key file.
  The private key remains outside the repository. Disabled inherited permissions
  on the private key and explicitly granted access to its owner.
- Created `C:/Users/BABAK/.ssh/config` with the `partsmall-server` alias, the given
  IP and username, the dedicated key, and strict host-key checking.
- No successful server login, remote file changes, database changes, application
  deployments, or website configuration changes occurred.

## Backups

No database backup was needed because no database work occurred. The local SSH
configuration did not exist before this request, so no existing configuration was
overwritten. The proposed remote installation below backs up any existing
`authorized_keys` file before adding the new key and preserves existing entries.

## Verification

- `ssh -G partsmall-server` resolved the expected username, IP, identity file,
  identity selection, and strict host-key checking.
- SSH key generation and the private-key permission command succeeded.
- `ssh -o BatchMode=yes -o ConnectTimeout=10 partsmall-server hostname` failed
  with `Permission denied (publickey,password)`. Automatic login is not yet active.
- Application tests are not applicable to this SSH configuration change.

## Blocker and Remaining Work

A working server login is required to install the public key for `ubuntu`. The
user was asked whether the provided login works from their terminal or requires
a different username or key. Once access is available, install the public key and
verify that `ssh -o BatchMode=yes partsmall-server hostname` succeeds.

Alternatively, run the following once in an already authenticated server shell as
`ubuntu`. This is a proposed command and has not been executed on the server:

```sh

mkdir -p "$HOME/.ssh"
chmod 700 "$HOME/.ssh"
if [ -f "$HOME/.ssh/authorized_keys" ]; then
    cp -p "$HOME/.ssh/authorized_keys" "$HOME/.ssh/authorized_keys.backup-$(date +%Y%m%d-%H%M%S)-$$"
fi
touch "$HOME/.ssh/authorized_keys"
if ! grep -qxF 'ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIDZx2SacoQOmD7lmXv0klBcm9fqx/CwxT2/D+8F9Hmjs partsmall-server BABAK' "$HOME/.ssh/authorized_keys"; then

```
